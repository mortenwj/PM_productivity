# Decision log — IFAR file-first processing workspace

Audit trail for the product brief. New entries append at the bottom.

## 2026-09-29 — Problem framing

- **Decision:** Primary pain is file-granular work presented as document/case metadata in BIF; v1 targets **in-case handler workspace**, not whole-module rewrite.
- **Rationale:** Conversation with PM; customer feedback on navigation and casework habits.
- **Status:** Accepted for brief.

## 2026-09-29 — Typical case size

- **Decision:** Most cases are **tens of files**; **rarely above ~50**; very large cases are exceptional.
- **Rationale:** PM input; Access Request Reports remain exception path, not default UX.
- **Status:** Accepted for brief.

## 2026-09-29 — Inline preview (D1)

- **Decision:** Use **inline file viewing** in split workspace (queue + preview + decisions), not one-file-at-a-time full-page navigation.
- **Status:** Accepted for brief.

## 2026-09-29 — Preview technology (D2)

- **Decision:** **Default Accusoft File Viewer**; consider alternatives only if spike fails (embed, redaction, performance).
- **Status:** Accepted for brief.

## 2026-09-30 — FIB FileViewer + Accusoft (verified)

- **Decision:** IFAR Process files use existing FIB **`FileViewer`** (`@si/360-view-components`); Accusoft embed **already implemented** via `GetFilePreviewInfo` + iframe.
- **Decision:** Separate **narrow spike** for `enableRedaction` (+ IFAR) URL params on `FileViewer` — not a new embed project.
- **Evidence:** `te-industry-public360` — `FileViewer.tsx`, `FilePreviewManager.cs`; consumers include `ai-views`, `case-components/FilePreview.tsx`.
- **Status:** Documented in `spike-ifar-fileviewer-redaction-params.md`.

## 2026-09-29 — Suggestion granularity (D3)

- **Decision:** Assisted decisions at **file level** and **document level** (“all files on this document”) with exception handling when histories diverge or file versions are newer.
- **Status:** Accepted for brief.

## 2026-09-29 — Suggestion source (v1)

- **Decision:** v1 suggestions are **rule-based from structured prior IFAR outcomes**, not ML/generative AI.
- **Rationale:** Accountability, audit, and customer trust.
- **Status:** Accepted for brief.

## 2026-09-29 — Handler accept/reject

- **Decision:** All suggestions require explicit **accept / edit / reject**; log which prior case drove acceptance.
- **Status:** Accepted for brief.

## Open — Match key for prior outcomes

- **Question:** What identity links “same file/document” across cases (document Recno, file version, external archive ID, title hash)?
- **Impact:** Wrong matches destroy trust in suggestions and bulk apply.
- **Owner:** TBD (PM + engineering + legal/compliance input).
- **Status:** Open.

## Open — Classified / sensitive bulk apply

- **Question:** When customer theme “sensitive/HR/training” applies, disable document bulk, extra confirm, or suppress suggestions?
- **Status:** Open; noted in brief out-of-scope partial for deep redesign.

## 2026-09-30 — Front-end stack (FIB)

- **Decision:** All new code for this workspace **must be built on FIB**, not BIF. Rationale: Public 360° maintains BIF and FIB; another BIF module would worsen inconsistency and maintenance.
- **Decision:** BIF may remain as **optional classic fallback** during rollout only — not the delivery target.
- **Status:** Accepted for brief; PRD/architecture must specify FIB entry point and design-system usage.

## 2026-09-30 — PFR corpus integrated

- **Decision:** Scope and problem framing aligned to **53 IFAR-tagged PFR Features** (`te-industry-public360/docs/bmad/ifar-pfr-research.md`, `ifar-pfr-index.csv`).
- **Decision:** v1 wedge prioritized to PFR clusters **document_volume**, **decisions_legal**, **redaction** (in-case); **dispatch_delivery**, **intake_email**, **innsynsoversikt_ui** explicitly fast-follow/out of v1 UI.
- **Status:** Reflected in `brief.md` and `addendum.md` § Product First Requests.

## 2026-09-30 — Archive Inspector integration intent

- **Decision:** Integrate **360° Archive Inspector** (PII/sensitive detection) into file overview + redaction flow — **reuse AI/FIB stack**, do not duplicate detection in IFAR.
- **Decision:** v1 target = **indicators on file rows** + **finding-guided redaction** (highlight/navigate + manual Accusoft redact); **one-click apply-all redactions** only after File Viewer / AI spike proves coordinate support.
- **Status:** Investigation captured in `addendum.md`; scope v1.1 / partner unless API spike is fast.
