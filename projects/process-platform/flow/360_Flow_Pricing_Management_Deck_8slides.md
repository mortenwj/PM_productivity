## Slide 1 — Title

**360° Flow — Pricing & packaging decision**

Commercial model for pilot → GA | Management approval

---

## Slide 2 — The ask

**We need alignment on:**

1. How we **land** Flow (fast uptake, Nordic buying norms).  
2. How we **capture return** on Process Framework R&D.  
3. What goes to **Enablement / catalogue** (meter, tiers, SKUs).

**Recommendation:** **Hybrid model (Option 3)** — foundation included in Public 360°, process capacity for scale, Enterprise for power; **Playbook** levels for sales conversations; **Process Engine** logic for overage above entitlement.

---

## Slide 3 — Context (why this decision now)

| Driver | Implication |
|--------|-------------|
| Major **R&D** in Flow runtime & ProcessView | Need a commercial story that funds ongoing investment |
| **Pilot** today → **GA** next | Set market expectation before catalogue freeze |
| **Nordic norm** | Workflow / lifecycle progression is **bundled in case platforms** — not sold as standalone BPM |

**Positioning:** Not “best process engine” — **who operationalizes administrative work most predictably and governably** inside Public 360°.

**We price:** Foundation · Process capacity · Enterprise power · Fixed implementation services.

## Slide 4 — Three options at a glance

| | **1 — Process Engine** | **2 — Playbook packages** | **3 — Hybrid** ✓ |
|--|------------------------|---------------------------|------------------|
| **Meter** | Per active production process | 3 capability levels (1 / multi / full platform) | Included foundation + N processes + packs + Enterprise |
| **Land** | First process cheap | Single Process Access | Foundation + generous included N |
| **Expand** | More processes | Add processes (~5 cap on platform fee), then vertical upgrade | Process packs + Enterprise tier |
| **Strength** | Familiar meter; scales with use | Best **sales narrative**; fixed implementation | **Land + return**; Nordic fit |
| **Risk** | Weak alone; BPM-style; gaming | Under-monetize past ~5 without upgrade | More SKUs; need “production process” definition |

**Scores (1–5, max 35):** Option 1 = **23** · Option 2 = **30** · Option 3 = **32**

## Slide 5 — Recommended model (Hybrid)

| Layer | Customer gets | Pricing |
|-------|---------------|---------|
| **A — Foundation** | ProcessView, milestones/stages, standard dialogs, auditability, **shipped building blocks only** (pilot) | **Included** in Public 360° / Basic |
| **B — Capacity** | Right to run **N production processes** | **Pilot: 2 included (all segments)** + packs above; GA segment model TBD |
| **C — Enterprise** | Portfolio/overview (when GA), advanced rules, advanced integrations, scale governance | **Premium tier** — operating model, not compliance paywall |
| **Services** | Onboarding, process rollout | **Fixed implementation packages** (Playbook) |

**Customer journey (unchanged):** Prove → Expand → Mature · Playbook Level 1 / 2 / 3 map to foundation + capacity + Enterprise.

**Pilot:** Time-boxed **expanded process entitlement** + fixed implementation; documented path to Standard / Enterprise at GA.

---

## Slide 6 — Guardrails & investment logic

**We will not:**

- Paywall **auditability**, basic lifecycle visibility, or role enforcement behind Enterprise  
- Position Flow as **standalone BPM** vs case platform  
- Promise **Enterprise features** not on GA roadmap (portfolio, full PMC self-service) without dates  
- Bespoke deals or **feature discounting** outside packages  

**Return economics:**

| | Land | Return |
|--|------|--------|
| **Revenue** | Foundation included | Process packs · Enterprise · implementation |
| **Strategic** | Pilot conversion, retention | Standardized delivery, services, cloud footprint |

**Inclusion = land economics · Capacity + Enterprise = return economics**
