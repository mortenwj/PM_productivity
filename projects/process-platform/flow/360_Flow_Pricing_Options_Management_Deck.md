## Slide 3 — Overview: three pricing options (compare & rate)

Three models on the table. **Rating scale:** 1 = weak · 3 = adequate · 5 = strong (for our goals: fast uptake + fair return on framework investment + Nordic/public-sector fit).

### Option 1 — Process Engine model (per active process)

**Structure**

- **Flow runtime / framework:** no or low separate platform fee (included in Public 360° or nominal).  
- **Revenue meter:** **per active production process** (same logic as today’s **360° Process Engine** in Commercial structure: priced **per process**, tiered by org size).  
- **Expansion:** more processes = more recurring revenue; integrations/rules may stay on existing module meters.

**How it works in practice**


| Element          | Logic                                                                          |
| ---------------- | ------------------------------------------------------------------------------ |
| Land             | Customer activates first process; pays little beyond P360 base                 |
| Grow             | Each new operational process (case type / template in prod) adds recurring fee |
| Enterprise depth | Not a separate tier — paid via process count + other modules                   |


**Strengths:** Familiar to Enablement/sales; scales with operationalization; low friction for “first process.”  
**Weaknesses:** Rare in Nordic case suites; definition/gaming risk; large orgs with few processes under-pay; weak “platform investment” story if base is free.

---

### Option 2 — Playbook consumption levels (sales packages)

**Source:** *Process Framework in Public 360° — Commercial Packaging & Sales Playbook*

**Structure**

- **One unified platform** — same engine/roadmap for all customers.  
- **Three commercial entry points** (capability + entitlement packages, not only a raw meter):


| Level | Package                   | Entitlement & delivery                                                                                                             | Sales message                                      |
| ----- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| **1** | **Single Process Access** | 1 activated process, managed configuration, standard automation, **fixed implementation package**                                  | Start small. Demonstrate value. Expand when ready. |
| **2** | **Managed Multi-Process** | Multiple processes, predictable ops model, **scalable to 5+ without platform fee increase**, structured implementation per process | Scale standardization safely.                      |
| **3** | **Full Platform Access**  | Self-service modeling, governance & portfolio visibility, advanced automation, version control ownership                           | Own your process architecture.                     |


**Growth model**

- **Horizontal:** add processes (structured implementation); **no platform fee increase beyond ~5 processes**.  
- **Vertical:** upgrade to Full Platform (modeling autonomy, governance, advanced automation).  
- **Journey:** Prove → Expand → Mature.

**Strengths:** Sales-ready; fixed implementation protects margin; matches customer maturity; procurement-friendly narrative.  
**Weaknesses:** Needs catalogue/SKU translation; “no platform fee to ~5” caps ARPU unless vertical upgrade is sold; must align feature GA (portfolio, self-service) with Level 3 promises.

### Option 3 — Hybrid model (recommended direction)

**Structure**


| Layer              | What customer gets                                                                                            | How we charge                                                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **A — Foundation** | ProcessView execution, milestones/stages, standard dialogs, progression auditability, shipped building blocks | **Included** in Public 360° / Basic (workflow as part of case platform)                                                              |
| **B — Capacity**   | Right to run **N production processes**                                                                       | **Included entitlement** (e.g. 5–10) + **process packs** beyond; can align list math with Process Engine **per process** for overage |
| **C — Enterprise** | Portfolio/overview (when GA), advanced rules lifecycle, advanced integration patterns, cross-org governance   | **Premium tier** — power and operating model, **not** basic compliance                                                               |
| **Services**       | Onboarding, process rollout                                                                                   | **Fixed implementation packages** (from Playbook)                                                                                    |


**Maps to Playbook without giving away investment**

- Level 1 ≈ Foundation + **1** process (+ implementation package).  
- Level 2 ≈ Foundation + **included multi-process** (e.g. up to 5) + packs.  
- Level 3 ≈ **Enterprise** layer on top of capacity.

**Strengths:** Fast uptake (Nordic bundle norm) + clear expansion (packs + Enterprise); separates land vs return; combines Playbook journey with Process Engine–style metering for overage.  
**Weaknesses:** More moving parts; requires crisp **“production process”** definition and Enablement SKUs.

## Slide 7 — Competitor lens (why not “BPM SKU” only)

**Nordic public case vendors (cBrain, KMD, ACOS, Sikri, Innofactor, etc.):**  
Workflow / lifecycle / approvals typically **embedded** in platform — **not** separate process-runtime products. *(Confidence: Low–Medium per research summary.)*

**Comparables:** Microsoft (user + capacity), enterprise vendors (quote-based platform), ECM suites (module/suite).

**Implication:** Lead with **“operational case progression included”**; monetize **scale and power**, not permission to run workflows.

## Slide 9 — What we will NOT do (guardrails)

From Playbook + governance:

- No **bespoke promises** outside standard packages  
- No **feature-based discounting**  
- No gating **auditability, role enforcement, basic lifecycle visibility** behind Enterprise  
- No positioning as **standalone BPM** competing with case platform narrative  
- No GA promise of **Enterprise features** still in backlog (worklists, full PMC self-service) without date qualifiers

**Sales checklist (every deal):** org tier | process entitlement | capability level | implementation package | expansion path communicated.

## Slide 11 — Investment capture (answer to “are we giving it away?”)

**Direct revenue:** process packs + Enterprise tier + implementation packages.  
**Indirect revenue:** higher P360 retention, more integrations, cloud footprint, services, cross-sell.  
**Strategic return:** switching cost, standardized delivery, reduced bespoke workarounds.

**Key message for management:** Inclusion is **land economics**; **capacity + enterprise** is **return economics**.
