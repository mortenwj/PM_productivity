## A. How release information is presented (last five releases)

Pages reviewed via MediaWiki: **6.6**, **6.7**, **6.8**, **6.9 (eDoc only)**, **6.10**.

### Common page anatomy

| Block | Purpose | Typical content |
|-------|---------|-----------------|
| **Release header table** | Planning & availability | Planned date; cloud + on-prem availability; disclaimer that dates/content may change; P&S approval for customer commitments |
| **Release documentation** (6.6–6.8) | Internal/customer comms | Links to help.360online.com external release note, ServiceNow KB, webinars, upgrade week |
| **New modules** | GA modules this release | Intro line + `== Module ==` per item; often `@owner #ADO`; **What’s new / Why it matters**; screenshots; **See also** module page |
| **News and improvements in existing module(s)** | Incremental module changes | Same subsection pattern; **What changed** / **Why it matters** common (6.10 AutoSaver, Mimir) |
| **New features and improvements in the core product** | Platform/core | Queue Monitor, FFUI, case references, etc. |
| **Technical notes** | SIF, on-prem docs, infra | Often TBA until late in release |
| **End of life of modules and features** | EOL announcements | **Announced** date, **Planned EOL**, alternatives, what happens next |
| **Coming soon (Ongoing Pilots)** | Pre-GA / pilot only | Standard disclaimer: *not GA*; internal use; will move to GA section when released |
| **Category** | Wiki housekeeping | `[[Category:360° Release information]]` |

### Module / feature subsection pattern (GA — e.g. 6.8 Search Assistant)

1. HTML comment with owners and ADO IDs: `<!--@Name #12345 -->`
2. Short **intro paragraph** (what it is, rename/positioning if relevant)
3. Bullet lists for capabilities, configuration, prerequisites
4. **Images** with descriptive captions (`[[Image:...]]` / `[[File:...]]`)
5. **See also** `[[Module page|…]]` and related release cross-links

### Pilot subsection pattern (e.g. 6.8 Process Models admin MVP, 6.7 “Process Models for 360 cases”)

- Lives under **Coming soon (Ongoing Pilots)** only
- Often notes **feature toggle** (e.g. `FT:ProcessManagementModule`)
- Shorter than GA sections; may reference internal webinar timestamp
- **Availability** stated explicitly (pilot customers only / internal)
- Less configuration detail until GA

- **360° Flow (Pilot)** already exists but is **thin** vs PRD and vs peer pilots
- Mature 6.10 module sections (GEMI, Fiks Arkiv WIP) use: **What’s new**, **Configuration**, **Migration**, **Important notes**, **See also**

==360° Flow (Pilot)==
<!-- @Tone, @Morten J. #414623 #410938 — Product: 360° Flow (formerly PAF / Process Automation Framework) -->

'''Availability:''' '''Internal and controlled pilot only''' — not generally available (GA). Functionality in this release is for validation with selected implementation partners and pilot customers. Licensing, packaging, and customer-facing product documentation are not finalised.

'''Earlier name:''' PAF — Process Automation Framework.

=== What it is ===

'''360° Flow''' is the governed operational execution layer for Public 360°. It is '''not''' a generic BPM or low-code workflow product. Flow provides structured, lifecycle-aware case progression inside the case workflow — using process models, progress plans, activities, milestones, stages, and rules — with '''ProcessView''' as the primary operational surface for case handlers.

Hosted Processes (sector-specific process packages) are planned as a commercial/service layer on top of Flow; they are out of scope for this pilot note unless explicitly enabled for your tenant.

=== What it solves ===

* '''Standardises''' case handling across repeatable administrative processes (equal treatment, traceability, role-based steps).
* '''Reduces manual coordination''' through defined activities, notifications, and runtime orchestration.
* '''Improves visibility''' of process status on the case (phases, milestones, stages) for case workers and managers.
* Supports '''quality at the point of work''' — registration and progression quality that affects later search, publishing, and archiving.

=== Key capabilities in the 6.10 pilot scope ===

Capabilities below reflect the current product slice. Items marked ''(emerging)'' are under active development and may not be enabled in all pilot tenants.

'''Process structure and execution (available in pilot)'''

* Define and bind '''process models''' to cases (stages, milestones, activities).
* Execute '''progress plans''' on cases — phases, activities, execute / edit / cancel / reactivate.
* '''Milestone''' and '''stage''' dialogs and views (lifecycle-oriented visibility on the case).
* '''Sub-processes''' via process dialogs where configured in the process model.
* '''ProcessView''' — process-centred operational UI on the case (`DMS/CaseDetails/ProcessView`).

'''Rules and automation'''

* '''DMN-based rules''' at runtime for configured scenarios.
* '''Notifications''' (e.g. email) driven by process configuration.
* Document-flow patterns: '''approval, review, dispatch''' where enabled in the progress plan (some routing remains transitional between legacy and React surfaces).
* '''Document-linked milestones''' — milestone triggers on document dispatch/receive and related orchestration (pilot tenants should validate their document categories and process templates).

'''Reusable operational patterns'''

* Shipped building blocks include milestone/stage patterns, notification patterns, consultation/approval flows, and standard process templates (implementation-led configuration).

'''Under development or emerging — do not promise for all pilots'''

* ''(emerging)'' '''Worklists''' and process-centric '''desktops / webparts''' for portfolio overview.
* ''(emerging)'' Broader '''PMC admin''' self-service UX (APIs exist; routed admin UI limited in current slice).
* ''(emerging)'' '''Share with''' — business logic and toolbox activity shipped in 6.10 timeframe; '''ProcessView may not yet expose all Share With UX''' — verify tenant configuration and host routing.
* ''(emerging)'' '''PMC import/export''' of process models (admin UI) — not full self-service PMC for all tenants.
* '''Functional / web-based process modelling''' and '''AI-assisted''' composition — future direction, not pilot scope.

=== Who it is for ===

| Role | Typical use in pilot |
|------|----------------------|
| Case worker / case handler | Execute activities, complete steps, progress the case in ProcessView |
| Registrar / administrative staff | Registration quality, metadata, process model binding where configured |
| Manager | Follow progress, deadlines, and bottlenecks on cases (case-level visibility today) |
| Process owner / Flow administrator | Govern process model structure with implementation support (PMC; admin/registrar-gated) |

=== Configuration and enablement ===

* Activation is '''implementation-led''' — not customer self-service in the pilot phase.
* Pilot features may require '''feature toggles''' and process-model configuration (PMC). Known product toggle (code): '''AsyncProcessModelLoading''' — affects whether process-model stage/milestone preparation runs asynchronously after bind (tenants may need wait/poll behaviour). Confirm display names in 360° Administrator / cloud portal with delivery; 6.8 pilot docs also referenced '''FT:ProcessManagementModule''' for process-management module scenarios.
* Process model and work-unit authoring today is '''consultant- and admin-oriented''' (XML/XAML work units); browser-based modelling is future direction.

=== Important notes (pilot) ===

* '''Not''' the legacy '''Workflow''' webpart product line — Flow uses the Process Platform runtime (`SI.Client.Api.Process` / ProcessView), separate from the All Workflows webpart.
* Some activity types and dialog paths are '''transitional''' (mixed BIF and React client actions). Pilot test plans should include your actual process templates.
* '''AI''' features (assisted modelling, agents in flow) are '''not''' part of this pilot.
* '''Licensing and pricing''' are not final — do not quote commercial terms from this page.
